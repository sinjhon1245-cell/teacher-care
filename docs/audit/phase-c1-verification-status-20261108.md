# Phase C 1차 — 검증 상태 표시 개선 (2026-11-08)

설계: [verification-status-design-20261107.md](verification-status-design-20261107.md) · 회귀 검사: `tools/check-phase-c1-status.js` · 데이터 규칙: `tools/check-data.js`(검증 범위 checks)

이 단계는 **표시 방식과 검증 범위 기록 구조**만 바꿔요. 지원 금액·기한·사업 수(16개 지역 / 192개 사업)는 바꾸지 않았고, 2026. 11. 20.·12. 3. 시행 예정 교원지위법은 반영하지 않았어요. 79개 항목을 한꺼번에 바꾸지 않았고, checks는 근거를 다시 확인한 5개 항목에만 넣었어요.

## 1. 바꾼 이유

- ‘YYYY. M. D. 최종 확인’은 그날 신청 가능 여부·조건까지 모두 확인했다고 읽힐 수 있어요. 실제로는 대부분 공식 자료와 대조한 날이에요.
- `reviewStatus: review-needed`는 데이터에만 있고 화면에는 보이지 않았어요. 사용자는 확인이 덜 된 항목과 끝난 항목을 구별할 수 없었어요.
- 공식 자료끼리 신청 기한이 다른 항목(충남 상담·회복, 경남 보호조치 비용)이 다른 항목과 똑같이 보였어요.

## 2. 문구 수정 전후

| 위치 | 수정 전 | 수정 후 |
|---|---|---|
| 지원 카드 아래 날짜(checks 없음, 기존 데이터) | `2026. 11. 7. 최종 확인 · 근거 자료` | `2026. 11. 7. 자료 확인 · 근거 자료` |
| 지원 카드 아래 날짜(checks.terms) | 〃 최종 확인 | `2026. 11. 7. 신청 조건 확인` |
| 지원 카드 아래 날짜(checks.route) | 〃 최종 확인 | `2026. 11. 7. 신청 경로 확인` |
| 지원 카드 아래 날짜(terms + route) | 〃 최종 확인 | `2026. 11. 7. 신청 조건·경로 확인`(둘 중 이른 날짜) |
| 원문 열람 불가 | `· 원문 게시물을 다시 확인하고 있어요` | `· 원문 게시물을 지금 열 수 없어요`(운영자 작업 상태처럼 쓰지 않음) |
| 근거 상자 머리 | `2026. 10. 26. 최종 확인 · 자료 30건` | `2026. 10. 26. 자료 확인 · 자료 30건` |
| 근거 상자 목록 | `· 2026. 10. 7. 확인` | `· 2026. 3. 6. 게시·시행, 2026. 10. 7. 확인`(sourceUpdatedAt이 있을 때만) |
| 회복·보호 ‘공식 근거’ | `3건 · 2026. 10. 3. 확인` | `3건 · 2026. 10. 3. 자료 확인` |
| 카드 제목 옆 상태(review-needed) | 표시 없음 | `조건 확인 필요` |
| 카드 제목 옆 상태(공식 자료 간 차이) | 표시 없음 | `자료 간 차이` |
| 카드 제목 옆 상태(source-unavailable) | 표시 없음 | `원문 열람 불가` |

‘확인 중’ 같은 운영자 작업 상태 문구는 쓰지 않아요. `exists`만 기록된 항목은 신청 조건을 확인한 것처럼 보이지 않도록 ‘자료 확인’으로 남겨요.

## 3. 상태 배지 — 한 카드에 하나만

| 우선순위 | 조건 | 배지 | 모양 |
|---|---|---|---|
| 1 | `status`가 ‘현재 시행 중’이 아님(운영 여부·방식이 다름) | 신청 전 확인 · 시범 운영 · 2026 신청 마감 | 기존 강조 배지(`badge-accent`) |
| 2 | 공식 기간이 지남(`validUntil` < 오늘) | 기간 확인 필요 + 기존 ‘기간 확인’ 안내 상자 | 기존 강조 배지 |
| 3 | 원문 게시물을 열 수 없음(`source-unavailable`) | 원문 열람 불가 | 테두리 배지(`badge-check`) |
| 4 | 공식 자료끼리 내용이 다름(`checks.conflict`) | 자료 간 차이 | 테두리 배지 |
| 5 | 일부 신청 조건 미확인(`review-needed`) | 조건 확인 필요 | 테두리 배지 |

- 사용자가 구분해야 하는 네 경우를 나눠요. 운영 여부가 불확실하면 1·2번, 기한·금액이 불확실하면 5번, 공식 자료끼리 충돌하면 4번, 원문을 볼 수 없으면 3번이에요.
- 3~5번은 경고색 없이 회색 테두리만 써요(`.badge-check`: `--surface` 배경, `--muted` 글자, `--border-strong` 테두리). 기존 강조 배지와 겹치면 앞 순위 하나만 보여요. 예: 전남권 P05~P07은 ‘신청 전 확인’만 보여요.
- 배지에는 `<span class="sr-only">상태: </span>`가 붙어서, 화면 읽기 프로그램은 ‘상태: 자료 간 차이’처럼 읽어요. 뜻은 색이 아니라 글자로 전해요. 배지는 탭 이동 대상이 아니에요.
- 모든 사업에 경고를 붙이지 않아요. 확인 완료(verified) 항목에는 배지가 없어요.

## 4. checks 구조(선택 필드, 하위 호환)

```js
checks: {
  exists: 'YYYY-MM-DD',   // 제도가 운영 중임을 공식 자료로 확인한 날(화면에는 날짜 범위를 바꾸지 않음)
  terms:  'YYYY-MM-DD',   // 대상·금액·기한·제외 조건을 원문으로 확인한 날 → ‘신청 조건 확인’
  route:  'YYYY-MM-DD',   // 신청 페이지·서식·접수처를 확인한 날 → ‘신청 경로 확인’
  conflict: '무엇이 다른지 한 문장'  // 공식 자료 간 차이 → ‘자료 간 차이’ 배지
}
```

- `reviewStatus`는 그대로 써요. checks가 없는 기존 항목은 이전처럼 verifiedAt으로 ‘자료 확인’을 보여요.
- 날짜를 자동으로 만들지 않아요(verifiedAt에서 채우지 않음). 출처 링크가 있다는 것만으로 terms를 채우지 않아요.
- **점검 규칙(`tools/check-data.js`, 오류)**:
  - 알 수 없는 키는 쓸 수 없어요.
  - 날짜는 YYYY-MM-DD이고 미래가 아니어야 하며, 항목의 verifiedAt보다 늦을 수 없어요. checks가 있으면 verifiedAt도 있어야 해요.
  - terms·route 날짜는 **그날 이후에 확인한 출처(`sources[].verifiedAt` ≥ 날짜)가 그 항목에 연결돼 있어야** 해요.
  - terms가 있으면 화면에 조건(대상·자격·금액·기한·서류)이 있어야 해요. route가 있으면 신청 방법·연락처·신청 링크가 있어야 해요.
  - conflict는 10자 이상 문장이어야 하고, reviewStatus가 review-needed여야 하며, 기간·주의 문구에 ‘확인’ 안내가 있어야 해요.
  - (2026-11-08 보완) conflict에 적은 기한·금액·횟수 값(6개월·1년·10일 등)은 카드 상세 문구에 그대로 있어야 해요. 운영 상태 배지가 ‘자료 간 차이’ 배지를 가려도 차이는 상세에서 보여요. → [release-readiness-phase-a-c1-20261108.md](release-readiness-phase-a-c1-20261108.md)
  - 모든 review-needed 항목은 무엇을 확인할지 기간·주의 문구로 알려야 해요.
  - 개수는 고정하지 않았어요(6건·7건 같은 숫자를 검사하지 않음).
- 오류가 나는지 직접 확인했어요(데이터 사본을 바꿔 실행):
  - 알 수 없는 키 → 오류.
  - terms를 미래 날짜로 바꾸면 미래 날짜·verifiedAt 초과·출처 미연결 세 가지 오류.
  - conflict 항목을 verified로 바꾸면 오류.
  - conflict 항목에서 확인 안내를 지우면 오류 2건.
  - 출처 확인일보다 이른 terms → 통과(정상).

## 5. 공식 자료 간 차이 안내

카드의 기존 ‘기간’ 문구가 이미 차이를 설명하고 있어서, 배지 하나만 더하고 같은 주의 문장을 반복하지 않았어요.

| 항목 | 무엇이 다른지 | 어디에 확인하는지(기간 문구) |
|---|---|---|
| 충남 상담·회복 지원 | 도교육청 신청 페이지는 위원회 의결일부터 **6개월**, 2026 기본계획·개정 길라잡이(2026. 10.)는 **1년** | 6개월 안에 신청하거나 1588-9331(3번 전문상담사)에 먼저 확인 |
| 경남 보호조치 비용 | 2026 매뉴얼 부록에 실린 2020년 고시는 결과 통지서를 받은 날부터 **10일**, 2026 기본계획은 기한을 적지 않음. 고시가 지금도 적용되는지는 확인하지 못함 | 통지서를 받으면 바로 교육활동보호담당관(055-268-1346)에 신청 기한 확인 |

경남 항목은 이번에 `reviewStatus`를 verified에서 review-needed로 바꿨어요. 그래서 `check-data` 주의가 10건에서 11건으로 늘었어요. 의도한 최신성 주의예요.

## 7. 검증

- `node tools/check-phase-c1-status.js`(새로 추가, CI `release-full-validation` content-and-links 단계에 등록):
  - app.js의 `checkedScope`·`statusBadge`·`sourceLine`을 그대로 떼어 와 가짜 데이터로 시나리오 A~I를 확인해요.
    - A 확인 완료
    - B 조건 확인 필요
    - C 원문 열람 불가
    - D checks 없음·exists만
    - E terms만·route만
    - F terms+route(이른 날짜)
    - G 자료 간 차이(조건 확인 필요보다 우선)
    - H 기간 지남(마지막 날까지는 배지 없음)
    - I 운영 상태와 겹침
  - ‘최종 확인’·‘확인 중’이 다시 들어오지 않는지 확인해요.
  - 배지는 하나뿐인지, 배지에 ‘상태:’ 화면 읽기 문구가 있는지, `.badge-check`에 경고색이 없는지 확인해요.
  - 실데이터 192개 전부에서: review-needed면 배지와 확인 안내가 있는지, conflict면 review-needed인지, checks가 있으면 확인 범위 문구가 보이는지 확인해요.
- 기존 회귀 검사 전부 통과:
  - check-public-updates, check-school-complaint-law, check-chungnam-region, check-jeonnamgwangju-region
  - check-pr26-source-integrity, check-pr20-readability
  - Phase A·B1·B2 accuracy
- `node tools/check-all.js --verbose`: DATA PASS(오류 0 · 주의 11), LINKS PASS(515개).
- 브라우저: release-browser-qa, ui-check.
- 200% 확대(720px·320px CSS 너비, 배율 2): 6개 카드 모두 가로 넘침 없음. 배지는 카드 안에 있고, 좁은 화면에서는 제목 아래 줄로 내려가요.
- 키보드: Tab으로 카드 안 링크를 차례로 지나가고, 배지는 건너뛰어요.
- 접근성 트리: `text: "상태: 자료 간 차이"`.

## 8. 남은 확인(이번에 바꾸지 않음)

- checks가 없는 나머지 항목은 계속 ‘자료 확인’으로 보여요. 원문 재확인 근거가 생길 때 항목별로 넣어요(일괄 채우기 금지).
- 경남 2020년 고시(통지 후 10일)의 현행 효력 — 경남교육청 회신이나 새 고시를 받으면 review-needed를 풀어요.
- 충남 신청 기한 6개월/1년 — 도교육청이 신청 페이지와 기본계획 중 하나로 정리하면 conflict를 지워요.
- 충남·전남광주 지역 단위 review-needed, 강원·대전 reviewBy(2026-11-02) 경과는 이전 단계부터 남은 주의예요.
- 2026. 11. 20.·12. 3. 시행 교원지위법 반영은 [pending-law-plan-2026-11-20-12-03.md](pending-law-plan-2026-11-20-12-03.md) 계획대로 시행일 이후에 해요.
- 공개 업데이트(data/updates.js)는 실제 배포할 때만 적어요. 이번 단계에서는 추가하지 않았어요.
