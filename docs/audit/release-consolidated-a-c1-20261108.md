## 10. 롤백 계획(force push·reset·이력 삭제 금지)

| 대상 | 방법 | 확인 |
|---|---|---|
| Vercel | 대시보드 Deployments → 직전 정상 Production(현재 기준 `dpl_De63LCDb8xgkkFcoDhKG3jDh4Eur`, `52d10ee`) → **Instant Rollback**. 코드 변경 없이 즉시 돼요 | 대표 주소 `asset-version`이 직전 값인지 |
| GitHub(main) | 통합 squash 커밋을 `git revert <sha>`로 되돌린 커밋을 만들어요. **asset version을 새 값**(예: `YYYYMMDD-2`)으로 올리고 일반 push해요 | CI 통과, main diff가 통합 전과 같은지(asset version·업데이트 제외) |
| GitHub Pages | revert push 뒤 자동 재빌드 | Pages 빌드 기록·주소의 `asset-version` |
| Netlify | 운영에 연결돼 있다면 Netlify 관리 화면에서 직전 배포로 Publish deploy. 지금은 main을 따르지 않는 것으로 보여 별도 확인이 필요해요 | 운영자 확인 |

- Vercel Instant Rollback만 하면 main은 새 판인 채로 남아요. 원인 수정 전까지 다음 main push가 다시 새 판을 배포하니, 코드 롤백(revert)을 함께 해요.
- revert한 판의 공개 업데이트도 함께 빠져요. 다시 배포할 때 실제 공개일로 다시 적어요.
