# 서울·경기·인천 콘텐츠 gap audit (2026)

- 처음 작성: 2026-10-04(Phase 3) · 대상 데이터: `data/regions/seoul.js`, `gyeonggi.js`, `incheon.js` (지원 찾기 `programs`, 회복·보호 `benefits`, 교육지원청 `offices`)
- 목적: 지역마다 정보의 깊이가 어디서 다른지 내부적으로 파악하고, 다음 확인 작업의 우선순위를 정해요.
- 원칙: **공식 자료로 확인한 내용만** 적어요. 한 지역에 자료가 없다고 다른 지역 값을 옮겨 적지 않아요. 확인하지 못한 칸은 화면에서 숨겨요.

## 판정 기준

| 판정 | 뜻 |
| --- | --- |
| 충분 | 무엇을 지원하는지, 대상, 신청 경로(연락처·링크), 해당하면 한도·기간이 모두 있고 근거 출처가 연결돼 있어요 |
| 부분적 | 제도가 있고 출처도 있지만 대상·신청 경로·한도·절차 중 일부가 비어 있어요 |
| 부족 | 제도가 있다는 사실 정도만 있고, 교사가 바로 행동할 정보가 거의 없어요 |
| 공식자료 미확인 | 2026년 공식 자료에서 그 지역의 해당 제도를 확인하지 못했어요 |

## 현재 상태는 한곳에서 관리해요(Phase 4)

- **원본 데이터**: `tools/data/regional-gaps.js` — 지역 × 영역마다 `status`(complete·partial·missing·unverified), `note`, `todo`, `evidence`(실제 지원 항목 이름 또는 `benefits:<id>`).
- **보는 곳**: `docs/maintenance-report.md`의 ‘지역별 gap’ 표와 ‘다음 점검 항목’(`node tools/check-all.js`로 자동 생성).
- **검사**: `node tools/check-data.js`가 모든 지역 × 영역이 있는지, 상태 값, complete가 아니면 `todo`가 있는지, `evidence`가 실제 데이터를 가리키는지 확인해요.
- 이 문서에는 판정 기준과 기록만 남기고 표는 다시 적지 않아요(두 곳에서 따로 고치다 어긋나지 않게).
