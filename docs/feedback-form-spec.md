# 의견 받기 양식(Google Form) 명세

사이트의 의견 받기 진입점에 연결할 설문 양식의 명세예요.

- **대표 카드**: 맨 아래 ‘선생님 곁에 · 서비스 안내’ 오른쪽(모바일은 아래)의 ‘의견을 들려주세요’ — [도움이 되었어요] [보완이 필요해요] 두 버튼(같은 무게), ‘의견 보내기 ↗’, 개인정보 안내.
- **상세 한 줄**: 상황별 도움 상황·회복·보호 제도·지원 찾기 유형 상세의 링크 복사·인쇄 아래 ‘정보가 달라졌거나 보완이 필요하면 알려주세요. 의견 보내기 ↗’(큰 카드를 반복하지 않아요).
- 모두 새 창으로 열리고(화면 읽기 프로그램에는 ‘의견 양식, 새 창’), 인쇄에는 나오지 않아요. 클릭해도 사이트 방문 기록(History)은 쌓이지 않아요.
- **현재 상태: 비활성.** 관리할 공식 양식 주소가 없어서 `data/common.js`의 `FEEDBACK_URL`은 빈 문자열이고, 운영 사이트에는 카드도 링크도 보이지 않아요(누를 수 없는 버튼·‘준비 중’ 표시 없음).
- 임의 주소를 만들거나 넣지 않아요. 아래 명세대로 양식을 만들고 관리자가 정해지면 그때 연결해요.

## 1. 양식 맨 위 안내(설명란에 그대로)

> 이 설문은 ‘선생님 곁에’ 안내 내용을 고치기 위한 것이에요. 답변은 안내 개선에만 쓰고, 개별 사안에는 답하지 않아요.
>
> **이 설문에는 학생·보호자·교직원의 이름, 학교명, 전화번호 등 개인을 식별할 수 있는 정보나 구체적인 사건 내용을 입력하지 마세요.**
>
> 지금 도움이 필요한 상황이라면 소속 학교·교육(지원)청 교육활동 보호 창구로 연락하세요. 위험하면 112.

## 2. 문항

| # | 문항 | 유형 | 선택지·안내 | 필수 |
| --- | --- | --- | --- | --- |
| 1 | 이 안내가 도움이 되었나요? | 객관식 | 도움이 되었어요 / 조금 도움이 되었어요 / 도움이 되지 않았어요 | 예 |
| 2 | 어떤 정보를 보셨나요? | 체크박스 | 홈 / 대응 절차 / 상황별 도움 / 회복·보호 / 지원 찾기 / 잘 모르겠어요 + **지역**(서울 / 경기 / 인천 / 공통) | 아니요 |
| 3 | 찾으려던 정보를 찾으셨나요? | 객관식 | 찾았어요 / 일부만 찾았어요 / 찾지 못했어요 | 아니요 |
| 4 | 이해하기 어려웠던 부분이 있나요? | 장문 | 안내: “어느 화면의 어떤 문구였는지 적어 주세요. 사건 내용은 적지 마세요.” | 아니요 |
| 5 | 잘못되었거나 바뀐 정보를 발견했나요? | 장문 | 안내: “어느 화면·어느 항목인지, 공식 안내 주소(있다면)를 적어 주세요. 개인정보·사건 내용은 적지 마세요.” | 아니요 |
| 6 | 추가되면 좋을 정보가 있나요? | 장문 | 안내: “필요한 정보의 종류만 적어 주세요.” | 아니요 |

장문 문항(4·5·6) 아래에도 같은 개인정보 안내를 한 줄씩 다시 보여 줘요.

### 자동 입력 문항(미리 채우기용, 단답형 5개)

사이트가 지금 보던 화면을 함께 보내도록 양식 맨 뒤에 단답형 문항 5개를 둬요. 제목은 “(자동 입력) …”으로 하고 설명에 “수정하지 않아도 돼요”라고 적어요. 필수로 하지 않아요.

| 칸(FEEDBACK_FIELDS) | 문항 제목 | 들어가는 값(예) |
| --- | --- | --- |
| `type` | (자동 입력) 의견 종류 | `helpful`(도움이 되었어요) · `needs-improvement`(보완이 필요해요) · `general`(의견 보내기) |
| `region` | (자동 입력) 지역 | `seoul` · `gyeonggi` · `incheon` · `common` |
| `page` | (자동 입력) 화면 | `home` · `proc` · `guide` · `care` · `support` |
| `item` | (자동 입력) 항목 | 제도 id(`special-leave`), 상황 id(`physical-assault`), 지원 유형(`legal`), 비교(`leave`), 단계(`step-3`) — 없으면 비어 있어요 |
| `url` | (자동 입력) 보던 주소 | 공유 주소(예: `…/teacher-care/?region=incheon&page=care&benefit=special-leave`) |

검색어, 체크 상태, 사용자가 입력한 내용은 어떤 칸에도 보내지 않아요.

## 3. 양식 설정

| 설정 | 값 | 이유 |
| --- | --- | --- |
| 이메일 주소 수집 | 사용 안 함 | 개인을 식별하지 않기 |
| 로그인 필요 / 응답 1회로 제한 | 사용 안 함 | 계정 정보를 남기지 않기 |
| 파일 업로드 문항 | 넣지 않음 | 캡처에 개인정보가 들어갈 수 있어요 |
| 응답 사본 보내기 | 사용 안 함 | 이메일 수집과 같아요 |
| 응답 확인 메시지 | “보내 주셔서 고마워요. 공식 자료로 확인한 뒤 안내에 반영해요. 개별 답변은 드리지 않아요.” | 기대 관리 |

## 4. 운영

- **담당자**: 양식 소유자(관리 가능한 계정)와 응답을 보는 사람을 정한 뒤에 연결해요. 담당자가 없으면 연결하지 않아요.
- **처리 순서**: 응답 확인 → 개인정보·사건 내용이 들어간 응답은 내용을 옮기지 않고 삭제 → ‘잘못된·바뀐 정보’는 공식 원문으로 확인 → `docs/annual-maintenance-checklist.md` 업데이트 절차로 반영. 제보만으로 데이터를 고치지 않아요.
- **보관**: 반영 여부를 정리한 뒤 원 응답은 정기적으로 지워요(예: 분기마다).
- **확인 주기**: 최소 월 1회.

## 5. 사이트에 연결하는 방법(양식이 준비된 뒤)

설정은 `data/common.js` 한 곳에만 있어요. 화면 코드(`app.js`)에는 주소를 적지 않아요.

1. 양식 편집 화면 ⋮ → **미리 채워진 링크 가져오기**에서 자동 입력 문항 5개에 아무 값이나 넣고 링크를 만들어요. 링크에 보이는 `entry.숫자`가 각 문항 번호예요.
2. `const FEEDBACK_URL = '';`에 `https://docs.google.com/forms/d/e/…/viewform`(링크에서 `?` 앞부분)을 넣어요.
3. `const FEEDBACK_FIELDS = { type: '', region: '', page: '', item: '', url: '' };`의 각 칸에 해당 `entry.숫자`를 넣어요. 미리 채우기를 쓰지 않으려면 비워 둬요(그러면 `forms.gle` 짧은 주소도 쓸 수 있어요).
4. `node tools/check-all.js` — 점검 도구가 주소 도메인(`docs.google.com/forms`·`forms.gle`), entry 형식(`entry.숫자`), 중복, 미리 채우기를 쓸 때 `…/viewform` 주소인지 확인해요. 그다음 asset version 올리기 → 커밋·푸시.
5. 운영 사이트에서 확인: 서비스 안내의 ‘의견을 들려주세요’ 카드가 보이는지, 세 링크(도움이 되었어요·보완이 필요해요·의견 보내기)와 상세 한 줄이 새 창으로 열리고 자동 입력 문항에 지역·화면·항목·의견 종류·주소가 채워지는지, 체크·검색어가 들어가지 않는지.

연결 전후 모두 사이트는 별도 서버나 저장소를 쓰지 않아요.
