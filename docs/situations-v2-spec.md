# 선생님 곁에 — 상황별 도움 V2 구현 명세

> 상태: 구현 전 확정 명세  
> 목적: 현재 16개 상황 중심의 `상황별 도움`을 2026년 서울·경기·인천 공식 자료에 맞춰 확장한다.  
> 중요: 이 문서는 교육활동 침해 여부를 자동 판정하기 위한 것이 아니라, 교사가 자신의 상황을 빠르게 찾고 즉시 행동·기록·지원으로 연결되도록 하기 위한 제품/데이터 명세다.

---

## 0. 핵심 목표

현재 `data/common.js`의 `SITUS`는 대표 상황 16개 중심이라 실제 현장에서 발생하는 폭행·협박·민원·부당간섭·녹음·온라인 유포·아동학대 신고·수사·회복 상황을 충분히 찾기 어렵다.

V2의 핵심 목표는 다음과 같다.

- 실제 교사가 사용하는 언어로 상황을 표현한다.
- 법률 용어를 몰라도 자기 상황을 찾을 수 있어야 한다.
- 긴급 상황은 안전 확보를 최우선으로 안내한다.
- 지금 먼저 할 일, 학교에 알릴 내용, 기록할 것, 하지 말 것을 명확히 안내한다.
- 서울·경기·인천을 선택하면 해당 지역의 실제 지원·기관·신청 경로와 공식 근거로 연결한다.
- 지역을 선택하지 않아도 전국 공통 수준의 기본 대응은 볼 수 있어야 한다.
- 서비스가 교육활동 침해 여부를 자동으로 단정하지 않는다.

## 1. 제품 구조 원칙

### 1.1 공통 상황 마스터 + 지역별 variant

상황 데이터를 서울·경기·인천 3벌로 복제하지 않는다.

```text
공통 상황 마스터
├─ 서울 regionVariant
├─ 경기 regionVariant
└─ 인천 regionVariant
```

사용자 화면에서는 지역별로 독립적인 서비스처럼 보여야 한다.

예:

- 인천 선택 → 인천 지원·기관·전화·공식 근거
- 경기 선택 → 경기 지원·기관·전화·공식 근거
- 서울 선택 → 서울 지원·기관·전화·공식 근거

공통 상황의 기본 의미는 공유하되, 실제 공식 사례·지원제도·신청경로·근거가 다르면 regionVariant에서 보완한다.

### 1.2 지역별 복제 금지

같은 상황을 다음처럼 3개로 만들지 않는다.

- `incheon-parent-homeroom-change`
- `gyeonggi-parent-homeroom-change`
- `seoul-parent-homeroom-change`

대신 하나의 상황 ID를 사용한다.

```js
{
  id: 'parent-demand-homeroom-change',
  ...
  regionVariants: {
    incheon: {...},
    gyeonggi: {...},
    seoul: {...}
  }
}
```

## 4. SITUS V2 데이터 모델

기존 `subject`, `t`, `ex`, `act` 중심 구조를 다음 형태로 확장한다.

```js

  id: 'parent-demand-homeroom-change',

  group: 'interference',

  title: '담임을 계속 바꿔 달라고 요구해요',

  subjects: ['보호자'],

  officialTypes: [
    '정당한 교육활동에 대한 반복적 부당간섭'
  ],

  contexts: [
    '학부모 상담',
    '민원',
    '학급 운영'
  ],

  keywords: [
    '담임교체',
    '담임 바꿔달라',
    '교사 교체'
  ],

  urgency: '교육지원청 신고 검토',

  stages: [
    '학교 초기 대응'
  ],

  supports: [
    '행정 지원',
    '갈등 중재'
  ],

  example: '',

  firstAction: '',

  report: '',

  evidence: '',

    incheon: {},
```

## 5. subject → subjects[] 마이그레이션

기존:

```js
subject: '학생'
```

폐기.

V2:

```js
subjects: ['학생', '보호자']
```

필터도 기존:

```js
s.subject === o
```

에서:

```js
s.subjects.includes(o)
```

로 변경한다.

목표는 복수 주체 상황이 필터에서 빠지는 구조적 오류를 없애는 것이다.

## 6. 사용자 상황과 공식 유형 분리

사용자가 보는 제목은 실제 교사 언어를 사용한다.

예:

```text
담임을 계속 바꿔 달라고 요구해요
```

공식 분류는 `officialTypes[]`에 둔다.

예:

```text
정당한 교육활동에 대한 반복적 부당간섭
```

사용자에게 법률 용어를 먼저 학습시키지 않는다.

## 7. legalCaution 원칙

사이트는 다음을 자동으로 교육활동 침해라고 단정하지 않는다.

특히 다음 상황에는 `legalCaution`을 적극적으로 사용한다.

- 생활지도 불응
- 일반적인 학부모 의견·요구
- 담임교체 요구
- 정보공개 청구
- 수업 녹음·촬영
- 아동학대 신고
- 사실과 다른 신고가 의심되는 상황
- 고소·고발
- 일반적인 집회·시위·항의

예:

```text
보호자의 의견 제시 자체만으로 교육활동 침해가 되는 것은 아니며,
목적·반복성·내용·교육활동에 미친 영향 등을 종합적으로 확인해야 해요.
```

또한 다음을 명확히 구분한다.

- 단순 생활지도 불응 ≠ 자동 교육활동 침해
- 정보공개 청구 자체 ≠ 특이민원
- 녹음 자체와 무단 배포는 동일한 판단이 아님
- 신고 내용이 인정되지 않음 ≠ 자동 무고

## 8. regionVariants 원칙

지역별로 모든 내용을 복제하지 않는다.

공통 데이터와 실제 지역 차이가 있는 경우에만 override한다.

예:

```js
regionVariants: {
  incheon: {
    sourceIds: [],
    supportAreas: ['학교민원·특이민원 지원']
  },

  gyeonggi: {
    sourceIds: [],
    supportAreas: ['학교민원·특이민원 지원']
  },

  seoul: {
    sourceIds: [],
    supportAreas: ['긴급 지원', '갈등 중재']
  }
}
```

지역별로 달라질 수 있는 내용:

- 해당 지역 공식 사례
- 해당 지역 공식 근거
- 지원사업
- 기관
- 대표번호
- 신청 방법
- 지역 특화 대응
- 실제로 달라지는 경우의 `firstAction`

전화번호·기관명은 가능한 한 기존 `{HOT}`, `{HOT1}`, `{HOT2}`, `{LEGAL}`, `{SOS}`, `{MEDIATE}` 토큰과 region `programs` 데이터를 활용한다.

## 10. 검색 기능

상황이 38개로 확대되므로 `상황별 도움` 상단에 검색 기능을 추가한다.

예:

```text
어떤 일이 있었나요?

[ 담임교체, 욕설, 녹음, 생기부, 아동학대... ]
```

검색 대상:

- `title`
- `keywords[]`
- `contexts[]`
- `officialTypes[]`
- `example`

검색 요구:

- 한국어 부분 검색
- 공백 차이에 과도하게 민감하지 않음
- 대소문자 차이 무시
- 제목뿐 아니라 현장 검색어로도 찾을 수 있음

필수 테스트 예:

- 담임 → 담임교체 상황
- 생기부 → 출결·생활기록부 상황
- 녹음기 → 보호자의 몰래 녹음 상황
- 밤에 전화 → 업무시간 외 개인 연락 상황
- 아동학대 → 아동학대 신고 상황
- 출근 → 심리·회복 상황

## 11. 검색 + 기존 faceted filter

검색 기능은 기존 상세조건 필터를 제거하지 않는다.

사용자는 다음 3가지 방식으로 찾을 수 있다.

1. 검색
2. 상세 조건
3. 큰 상황 11개

검색어와 상세 조건을 동시에 사용하면 AND 방식으로 결과를 좁힌다.

기존 필터 그룹 내부의 OR 동작은 유지한다.

- 외부인
- 기타

`subjects[]` 기준으로 필터링한다.

### 상황 유형

V2의 38개 상황과 `officialTypes[]`를 충분히 찾을 수 있도록 재설계한다.

기존 12개 옵션을 그대로 유지할 필요는 없다.

원칙:

- 지나치게 법률용어 중심으로 만들지 않는다.
- 사용자에게 이해 가능한 표현을 쓴다.
- 38개 상황이 의미 있게 분류되어야 한다.
- 법적 판정처럼 보이지 않아야 한다.

### 나머지

다음은 현재 구조를 최대한 유지한다.

- 긴급성
- 처리 단계
- 지원 유형

## 14. 공통 모드

지역을 선택하지 않아도 38개 상황을 검색·확인할 수 있어야 한다.

공통 모드에서는 다음을 노출하지 않는다.

- 특정 지역 전화번호
- 특정 지역 사업명
- 특정 지원기관

대신 기존 `NEUTRAL_TERMS`와 전국 공통 근거를 사용한다.

지역별 지원이 필요한 버튼을 누르면 근무 지역 선택을 유도한다.

## 15. 공식 근거

### 공통

- 교육부 「교육활동 보호 매뉴얼」

상황별 도움에서는 각 지역 `sources[].uses`에 `guide`가 포함된 자료만 사용한다.

## 20. 가장 중요한 판단 원칙

이 서비스는 교육활동 침해 자동 판정기가 아니다.

사용자가 불안한 상황에서 법률 용어를 몰라도 자기 상황을 찾고,

> 지금 무엇부터 해야 하는지

확인할 수 있어야 한다.

따라서 모든 상황에 다음 원칙을 적용한다.

- 실제 교사 언어 사용
- 법률적 단정 최소화
- 긴급 상황은 안전 최우선
- 기록할 것 명확히 안내
- 혼자 대응하지 않도록 학교·교육(지원)청·전문지원으로 연결
- 현재 선택 지역의 실제 지원으로 연결
- 현재 선택 지역의 공식 근거를 명확히 표시
- 지역 자료가 없으면 다른 지역 자료로 대체하지 않음
- 근거가 부족하면 “추가 검증 필요”로 남김
