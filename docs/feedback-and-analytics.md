# 안내별 의견과 방문 통계 — 구조·개인정보·운영 절차

「선생님 곁에」는 방문자 수를 보여 주는 사이트가 아니에요. 선생님이 정보를 찾았는지, 안내가 충분했는지, 무엇을 고쳐야 하는지를 알기 위한 장치만 둬요.

- 방문자·응답 수는 **화면에 보여 주지 않아요**. 운영자만 Vercel 대시보드와 집계 도구로 봐요.
- 피드백은 **응답 건수**예요. ‘도움이 되었어요 100건’을 ‘교사 100명이 도움받았어요’로 쓰지 않아요(같은 사람이 다른 기기에서 다시 답할 수 있어요).

## 2. 안내별 의견(‘이 안내가 도움이 되었나요?’)

### 화면

- 위치: **지원 찾기의 각 지원 카드 맨 아래**, 그리고 회복·보호 제도 상세·상황별 도움 상황 카드·지원 유형 공통 기준의 ‘링크 복사·인쇄’ 아래. 홈·팝업·큰 카드는 없어요.
- 선택: 👍 도움이 되었어요 / 💬 정보가 부족해요 → (선택하면) 찾는 정보가 없어요 · 안내가 이해하기 어려워요 · 정보가 오래된 것 같아요 · 링크가 제대로 열리지 않아요 · 이유 없이 보내기
- 자유 입력 칸은 없어요(피해 사례·개인정보가 실수로 들어오지 않게).
- 보내는 동안 버튼이 잠기고 ‘보내는 중이에요…’가 보여요. 서버가 저장에 성공했다고 답할 때만 ‘○○로 의견을 보냈어요. 고마워요.’로 바뀌어요. 실패하면 ‘의견을 저장하지 못했어요. 잠시 뒤 다시 눌러 주세요.’가 보이고 다시 누를 수 있어요.
- 같은 기기·브라우저에서 같은 지역의 같은 안내에는 다시 묻지 않아요(`localStorage`의 `teacher-care-feedback-v1`에 응답 종류·날짜만). 다른 안내·다른 지역은 따로 답할 수 있어요.
- 인쇄 화면에는 나오지 않아요. 검색·유형 필터·지역 선택·링크 이동·공유 주소·방문 기록은 그대로예요.
- **버튼은 서버가 ‘준비됨’(`GET /api/feedback` → `{ "ready": true }`)이라고 답할 때만 그려요.** 저장소를 연결하기 전, GitHub Pages, 파일로 연 화면에서는 아무것도 보이지 않고, 서비스 안내 문장도 지금과 같아요. 저장되지 않는 버튼은 나오지 않아요.

### 서버(`api/feedback.js`)와 저장 값

| 받는 값 | 허용 범위 |
| --- | --- |
| `region` | `common` + 12개 지역 id(`tools/check-data.js`가 `REGION_ORDER`와 같은지 확인) |
| `kind` / `id` | `program`(지원 카드: 이름으로 만든 `p-` + 8자리 id) · `benefit` · `situ` · `type` / 영문 소문자·숫자·하이픈 64자 이내 |
| `choice` | `helpful` · `needs-more` |
| `reason` | `needs-more`일 때만 `missing` · `unclear` · `outdated` · `broken-link` (없으면 빈 값) |

- 다른 칸이 하나라도 있으면(예: 글 입력) 통째로 거절해요(400). 본문 1KB 초과도 거절해요.
- 같은 사이트에서 보낸 요청만 받아요(`Origin`과 `Host`가 같아야 함, 아니면 403). `Content-Type: application/json`만(415).
- 저장(Upstash Redis, 건수만 더함):
  - `fb:day:YYYY-MM-DD`(한국 날짜) 해시의 `지역|종류:id|응답|이유` 필드 +1 — 400일 뒤 자동 삭제
  - `fb:total` 해시의 같은 필드 +1(누적)
- **저장하지 않는 것**: IP 주소, 브라우저·기기 정보, 쿠키, 시각(날짜만), 자유 입력, 검색어, 체크 상태.
- 응답: 저장소에 실제로 더해졌을 때만 `200 { ok: true }`. 저장소 미연결 503, 저장 실패 502.
- 비밀키는 Vercel 환경 변수에만 있어요. 브라우저 코드·저장소(Git)에는 없어요. 공개 조회 경로는 없어요(`GET`은 준비 여부만).
- 한계: 로그인·IP 기록이 없어서 같은 사람이 여러 기기·브라우저로 반복해서 보내는 것은 막지 못해요. 건수는 개선 방향을 보는 참고값으로 써요. 필요하면 Vercel Firewall의 속도 제한 규칙을 `/api/feedback`에 걸어요.

### 켜는 방법(운영자)

1. Vercel 대시보드 → teacher-care 프로젝트 → **Storage** → **Upstash(Redis)** 를 만들고(무료 플랜) 이 프로젝트에 연결해요. 먼저 **Preview** 환경에만 연결하는 것을 권해요.
   - 연결하면 `KV_REST_API_URL`, `KV_REST_API_TOKEN`, `KV_REST_API_READ_ONLY_TOKEN` 환경 변수가 생겨요(이름이 `UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN`이어도 동작해요).
2. 의견 기능 PR의 미리보기를 다시 배포(Redeploy)해요. 미리보기 주소에서 확인해요.
   - `미리보기주소/api/feedback`이 `{"ready":true}`인지
   - 지원 찾기 카드 아래에 의견 줄이 보이는지, 눌렀을 때 ‘보냈어요’로 바뀌는지
   - `node tools/feedback-report.js`(아래)에 그 응답이 1건으로 보이는지
3. 확인되면 Production 환경에도 같은 저장소를 연결하고, PR을 병합·배포해요. 이때 `data/updates.js` 항목과 asset version을 배포일로 맞춰요.
4. 끄려면 `data/common.js`의 `FEEDBACK_API`를 빈 문자열로 바꿔 배포하거나, Vercel에서 저장소 연결을 해제해요(서버가 ‘준비 안 됨’으로 답해 버튼이 사라져요).

### 집계(운영자, 대시보드 없이)

```bash
KV_REST_API_URL=… KV_REST_API_READ_ONLY_TOKEN=… node tools/feedback-report.js --days=28
```

- 날짜별·주별(월요일 시작) ‘도움이 되었어요’·‘정보가 부족해요’ 건수, ‘정보가 부족해요’가 많은 안내 20개(이유별), 지역별 합계, 누적 건수를 보여 줘요. `--json=파일`로 저장할 수 있어요.
- 지원 카드 id는 현재 데이터의 카드 이름으로 되돌려 보여 줘요(카드 이름을 바꾸면 새 id가 되고, 예전 id는 ‘이름이 바뀌었거나 없어진 카드’로 나와요).
- 토큰은 읽기 전용 토큰을 쓰고, 화면 캡처·문서·채팅에 붙이지 않아요. Upstash 콘솔의 Data Browser에서도 같은 해시를 볼 수 있어요.
- 처리: ‘정보가 부족해요’가 모인 안내부터 공식 원문으로 다시 확인하고 `docs/annual-maintenance-checklist.md` 절차대로 고쳐요. 건수만으로 안내를 바꾸지 않아요.

## 3. 방문 통계(Vercel Web Analytics)

- 코드: `data/common.js`의 `WEB_ANALYTICS`(기본 `false`). `true`이고 `*.vercel.app` 주소일 때만 `/_vercel/insights/script.js`를 넣어요. GitHub Pages에는 넣지 않아요.
- 보내는 주소에는 `region`·`page`·`type`·`benefit`·`compare`·`situ`·`step`만 남기고 나머지 값과 `#…`은 지워요(검색어 등은 원래 주소에 없지만 한 번 더 막아요). 쿠키를 쓰지 않아요.
- 켜는 방법: Vercel 대시보드 → 프로젝트 → **Analytics** → **Enable** → `WEB_ANALYTICS = true`로 바꿔 배포 → 서비스 안내 문장에 ‘방문 통계는 쿠키 없이 페이지 조회 수만 집계해요’가 함께 보여요.
- 보는 곳: Vercel 대시보드 → 프로젝트 → **Analytics**(방문자·페이지 조회, 일/주 단위, 많이 본 주소 = 지역·화면·항목). Hobby는 최근 1개월만 볼 수 있고 월 50,000 이벤트를 넘으면 수집이 멈춰요.
- 상황별 도움·지원 찾기 안의 이동은 주소(`?region=…&page=…`)가 바뀌는 방식이에요. 같은 화면 안에서 주소가 바뀌는 이동이 조회로 따로 잡히는지는 켠 뒤 대시보드에서 한 번 확인해요.
