# 교사 사용성 테스트 가이드

- 대상 사이트: https://sinjhon1245-cell.github.io/teacher-care/ (운영 사이트 그대로, 테스트용 기능 없음)
- 성격: **문제를 찾기 위한 소규모 형성 평가(formative usability test)**예요. 점수를 매기거나 사이트를 ‘합격’시키는 시험이 아니에요.
- 결과 기록: `docs/usability-results-template.md`를 복사해 실제 관찰한 것만 적어요.
- 이 테스트 결과가 나오기 전에는 메뉴 이름·순서·홈 구성 같은 UX를 미리 바꾸지 않아요. 결과를 보고 다음 단계에서 고쳐요.

## 1. 참여자

- **5~10명** 권장. 아래가 섞이도록 모아요(한 사람이 여러 조건에 해당해도 돼요).
  - 학교급: 초등 / 중등
  - 담임 / 비담임
  - 경력: 저경력(5년 미만) / 중경력(5~15년) / 고경력(15년 이상)
  - 근무 지역: 서울 / 경기 / 인천
  - 기기: PC와 휴대전화를 비슷한 비율로
- 이름 대신 **P01, P02, P03 …**으로만 기록해요. 학교명·연락처는 결과 문서에 적지 않아요.
- **개인적인 교육활동 침해 경험이 있는지 묻지 않아요.** 참여자가 스스로 이야기해도 기록하지 않고, 과제로 돌아가도록 부드럽게 안내해요.

## 2. 동의와 안전

진행 전에 말로 확인하고 동의를 받아요.

- 사이트를 평가하는 것이지 참여자를 평가하는 것이 아니에요.
- 언제든 멈추거나 그만둘 수 있어요. 불편한 과제는 건너뛰어도 돼요.
- 화면 녹화·녹음은 동의할 때만 하고, 얼굴은 찍지 않아요. 녹화 파일은 결과를 정리한 뒤 지워요.
- 시나리오는 가상의 상황이에요. 실제 사안이 있다면 이 테스트가 아니라 학교·교육(지원)청 창구로 안내해요.

## 3. 준비

- 기기마다 **새 시크릿(비공개) 창**으로 시작해요. 이전에 저장된 지역·체크가 남지 않게 하려는 거예요.
- 시작 화면은 운영 사이트 첫 주소예요. 지역을 미리 골라 주지 않아요(첫 화면의 지역 선택도 관찰 대상이에요).
- 진행자 1명(안내), 기록자 1명(시간·클릭·뒤로가기 기록)이 좋아요. 혼자라면 화면 녹화를 켜고 나중에 기록해요.
- 준비물: 시나리오 카드(과제 문구만 적힌 종이 6장), 타이머, 결과 기록표.
- 과제 순서: A~E는 참여자마다 순서를 바꿔요(예: P01 A-B-C-D-E, P02 B-C-D-E-A …). **F(공유)는 항상 마지막**이에요(앞에서 찾은 내용을 보내는 과제라서).

## 4. 진행 스크립트

처음에는 아래 문장만 말해요.

> “교사를 위한 교육활동 보호·대응 안내 사이트입니다. 아래 상황을 보고 필요한 정보를 직접 찾아주세요.
> 생각나는 것을 소리 내어 말하면서 해 주시면 큰 도움이 돼요. 다 찾았다고 생각되면 ‘찾았어요’라고 말씀해 주세요.”

**하지 않을 말**(유도 금지)

- “회복·보호를 눌러보세요.” · “검색창을 사용하세요.” · “위쪽 메뉴를 보세요.”
- 메뉴 이름, 버튼 이름, 화면 위치를 먼저 말하지 않아요.
- 참여자가 물으면: “평소에 찾으시는 방법대로 해 보세요.”
- 3분 동안 진전이 없거나 참여자가 포기하면 그 과제를 끝내고 ‘HelpRequested’ 또는 실패로 기록해요. 그 뒤에 정답 경로를 알려 줄 필요는 없어요.

## 5. 시나리오(6개)

각 과제는 카드의 문장을 그대로 읽어요. 아래 ‘진행자 참고’는 참여자에게 보여 주지 않아요.

### Scenario A — 폭언 + 회복

> “보호자가 반복적으로 전화로 폭언을 했습니다. 오늘은 출근하기도 힘든 상태입니다. 지금 무엇을 할 수 있는지 찾아보세요.”

- 성공: 다음 중 **2가지 이상**을 스스로 찾아 말함 — 해당 상황 안내, 특별휴가, 병가, 상담(심리) 지원
- 관찰: 첫 메뉴(FirstClick) · 상황별 도움 발견 · 특별휴가 발견 · 병가 발견 · 상담 지원 발견
- 진행자 참고(관련 화면): 상황별 도움 `private-verbal-abuse`(1:1 전화·문자 욕설), `verbal-abuse` · 회복·보호 `special-leave`, `sick-leave` · 지원 찾기 ‘상담·회복’

### Scenario B — 녹음

> “보호자가 학생 가방에 녹음기를 넣은 것 같습니다. 어디부터 확인해야 할까요?”

- 성공: 녹음 관련 상황 안내에 도달하고, 처음 할 일(기록·보고 등)을 말함
- 관찰: 녹음 관련 상황 발견 · 참여자가 사이트를 보고 **법적 결론을 단정**하는지(예: “무조건 불법이니 처벌된다”) · 대응 절차로 이어지는지
- 진행자 참고: 상황별 도움 `hidden-parent-recording`, `class-recording-filming` · 대응 절차
- 단정적 법률 해석이 보이면 어떤 문구를 보고 그렇게 이해했는지 기록해요(Misunderstanding). 사이트가 그렇게 읽히게 했다면 Severity를 높게 봐요.

### Scenario C — 장기 회복

> “교육활동 침해 이후 치료가 오래 필요할 것 같습니다. 병가와 휴직의 차이를 찾아보세요.”

- 성공: 병가와 휴직(질병휴직)의 차이를 한 가지 이상 말하고, **일반과 공무상이 다르다**는 것을 말함
- 관찰: 회복·보호 발견 · 비교(휴가·병가 비교, 질병휴직 비교) 발견 · 일반/공무상 구분 이해
- 과제가 끝난 뒤 이해 확인 질문 1개(정답을 알려 주지 않아요): “교육활동 침해로 인정되면 공무상 질병휴직이 되나요?”
  - 사이트 기준 답: 아니요, 공무상 요양 승인을 따로 받아야 해요. 다르게 답하면 Misunderstanding으로 기록
- 진행자 참고: 회복·보호 → 비교 `leave`, `disease` · 제도 `disease-leave`, `official-disease-leave`, `sick-leave`, `official-sick-leave`

### Scenario D — 안전

> “상대방의 위협이 계속되고 있습니다. 지금 받을 수 있는 보호와 지원을 찾아보세요.”

- 성공: 긴급 대응(위험하면 112)과, 보호조치(분리 등) 또는 경호·안전 지원 중 하나 이상을 찾음
- 관찰: 긴급 대응 인지 · 보호조치(즉시 분리·보호조치 요청) · 경호/안전 지원 발견
- 진행자 참고: 상황별 도움 `specific-threat`, `stalking-approach`, `object-threat` · 회복·보호 `separation`, `protection-request` · 지원 찾기 ‘안전·경호’

### Scenario E — 신고

> “아동학대 신고를 받았습니다. 어떤 지원을 받을 수 있는지 찾아보세요.”

- 성공: 해당 상황 안내에 도달하고, 법률 지원 또는 수사·소송 지원 중 하나 이상을 찾음
- 관찰: 상황별 도움 발견 · 법률 · 수사·소송 지원 발견
- 진행자 참고: 상황별 도움 `child-abuse-report` · 지원 찾기 ‘법률’, ‘수사·소송’(인천은 ‘아동학대 피신고 교원 지원’ 항목도 있어요)

### Scenario F — 공유(항상 마지막)

> “찾은 내용을 동료 교사에게 보내려고 합니다.”

- 성공: 링크를 만들어(링크 복사 또는 주소창 복사) 그 링크를 새 창에 붙여 넣었을 때 **같은 내용이 열림**
- 관찰: ‘링크 복사’ 발견 여부 · 주소창을 복사하는지 · 실제로 공유 URL을 쓰는지 · 새 창에서 같은 지역·같은 항목이 열리는지
- 진행자 참고: 제도·상황·지원 유형·대응 단계 상세 아래의 ‘링크 복사’. 공유 주소에는 보던 지역이 들어가요(공통은 `region=common`)
- 참여자가 카카오톡 등 실제 메신저로 보내려 하면, 실제 전송 대신 메모장에 붙여 넣게 해요(개인 연락처 사용 금지)

## 6. 기록 항목(시나리오마다)

| 항목 | 적는 법 |
| --- | --- |
| Participant | P01, P02 … |
| Scenario | A~F |
| Success | 성공 / 부분 성공 / 실패 (각 시나리오의 성공 기준) |
| Time | 과제 문장을 다 읽은 순간부터 ‘찾았어요’ 또는 중단까지(초). **관련 화면 첫 도달 시각**도 따로(60초 기준 계산용) |
| Clicks | 메뉴·버튼·링크·칩·펼치기 누른 횟수(스크롤·입력 제외) |
| FirstClick | 처음 누른 것(예: 상단 ‘상황별 도움’, 홈 카드 이름) |
| SearchUsed | 예 / 아니요 |
| SearchQuery | 입력한 검색어 그대로(개인 정보가 들어가면 적지 않아요) |
| BackCount | 브라우저 뒤로가기 + 이전 화면으로 돌아간 횟수 |
| Issue | 막힌 지점·헤맨 지점(관찰한 사실) |
| Misunderstanding | 잘못 이해한 내용과 그렇게 이해한 문구 |
| HelpRequested | 예 / 아니요(무엇을 물었는지) |
| Severity | Critical / High / Medium / Low(아래 기준) |
| Notes | 참여자가 한 말(원문 그대로), 기기, 지역 선택 |

## 7. Severity 기준

| 등급 | 기준 |
| --- | --- |
| Critical | 잘못된 행동을 하게 만듦 · 중요한 안전 정보(112·분리·보고)를 찾지 못함 · 법적 의미를 심각하게 오해함 |
| High | 주요 기능을 반복해서 찾지 못함 · 여러 사람이 같은 잘못된 메뉴로 감 |
| Medium | 찾기는 하지만 오래 걸림 · 같은 문구가 반복해서 혼란을 줌 |
| Low | 작은 시각적 불편 · 사소한 표현 |

한 문제를 여러 사람이 겪으면 등급을 올릴지 결과 정리 때 함께 판단해요.

## 8. 성공 기준(초기 참고값)

| 지표 | 참고 기준 | 계산 |
| --- | --- | --- |
| 핵심 정보 발견 | 80% 이상 | A~E에서 ‘성공’인 과제 수 ÷ 수행한 과제 수 |
| 60초 안에 관련 화면 도달 | 70% 이상 | 관련 화면 첫 도달 60초 이하 과제 수 ÷ 수행한 과제 수 |
| 공유 기능 발견 | 60% 이상 | F에서 ‘링크 복사’를 스스로 찾은 참여자 ÷ F 수행 참여자 |
| 중대한 오해 | 0건 목표 | Critical 등급 Misunderstanding 수 |

- 5~10명 규모라 **절대적인 성능 점수로 쓰지 않아요.** 기준에 못 미친 지표는 “어디서 왜 막혔는지”를 찾는 출발점이에요.
- 기준을 넘었더라도 Critical·High 문제는 따로 다뤄요.

## 9. 끝난 뒤

- 마무리 질문(선택, 짧게): “가장 찾기 어려웠던 것은?”, “실제 상황이라면 이 사이트를 다시 쓰시겠어요? 왜 그런가요?”
- 결과는 `docs/usability-results-template.md` 사본에 **관찰한 것만** 적어요. 해석·개선 아이디어는 따로 칸이 있어요.
- 녹화 파일은 결과 정리 뒤 지워요.
