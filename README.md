# 선생님 곁에 — 교육활동 보호·대응 가이드

교육활동 중 문제가 생긴 선생님이 **지금 무엇을 해야 하는지** 빠르게 판단하도록 돕는 정적 웹서비스예요.
대응 절차·상황별 도움은 전국 공통으로 두고, 대표번호·교육지원청·지원(제도와 기관 연락처)은
근무 지역(현재 서울·경기·인천 베타)의 공식 자료를 바탕으로 보여 줘요.

화면은 네 개이고 역할이 나뉘어요.

| 화면 | 역할 | 주요 기능 |
| --- | --- | --- |
| 홈 | 시작 | 지역 대표번호 패널, 지금 필요한 도움 선택, 절차 요약(진행 표시), 내 교육지원청 찾기, FAQ |
| 상황별 도움 | 판단 → 선택 → 결과 | 상세 조건(주체·유형·긴급성·단계·지원, 데스크톱은 펼침·모바일은 접힘) → ‘○개 상황을 찾았어요’ 결과. 조건이 없으면 8가지 큰 상황. 결과마다 ‘지금 먼저 할 일’과 관련 대응 절차·관련 지원 보기 |
| 대응 절차 | 실행 | 4단계 stepper, 단계별 진행 체크(이 기기에만 저장), 역할별 할 일·주의·다음 단계 |
| 지원 찾기 | 연결 → 유형 선택 → 신청·상담 | 지역 지원 허브(대표번호 + 바로 이용하기), 도움 유형 선택 → ‘○○ 지원 N건’, 카드별 행동 버튼(온라인 신청·전화·카카오톡·공식 안내) |

빌드 도구·프레임워크 없이 HTML·CSS·바닐라 JS로만 동작하고, GitHub Pages에서 그대로 배포돼요.

## 파일 구조

```
index.html              스크립트 로드 순서 정의(공통 → 지역 → 화면)
style.css               전체 스타일(모바일 반응형 포함)
app.js                  화면 렌더링·상태 관리. 특정 지역 이름·번호를 두지 않아요
data/
  common.js             전국 공통 데이터 + 지역 등록 도구(registerRegion)
  regions/
    seoul.js            서울특별시
    gyeonggi.js         경기도
    incheon.js          인천광역시
tools/
  check-data.js         지역 데이터 점검(배포 전 실행)
```

### 공통 데이터(`data/common.js`)

절차(`STEPS`, `STEP_DETAIL`), 빠른 안내(`QUICK`), 상황별 도움(`SITU_GROUPS` 큰 상황 + `SITUS` 세부 상황, `g`로 연결, 상세 조건 `FILTER_DEFS`), 단계별 진행 체크(`STEP_DETAIL[].checks`), 보호조치(`PROTECTIONS`), FAQ,
지원 유형(`SUPPORT_TYPES`)처럼 **어느 지역에서나 같은 내용**만 둬요.

공통 데이터에 넣을 수 있는 것은 다음 둘 중 하나에 근거한 내용뿐이에요.

- 법령: 「교원의 지위 향상 및 교육활동 보호를 위한 특별법」과 시행령(분리 조치, 지역교권보호위원회, 교원보호공제, 교육활동보호센터 등)
- 교육부 「교육활동 보호 매뉴얼」 등 전국 공통 지침(특별휴가 기준, 사안 처리 절차·기한 등)

시·도가 따로 운영하는 사업 이름, 전화번호, 신청 방법, 지원 금액은 공통 데이터에 적지 말고 지역 데이터나 토큰으로 처리해요.
화면에 보이는 공통 근거는 `COMMON_PUBLIC_SOURCES`(교육부 매뉴얼·법령 등 전국 공통 공식 자료)에만 적어요. 특정 시·도 자료는 넣지 않아요.
공통 기준을 여러 시·도 자료로 교차 확인한 기록은 `VALIDATION_SOURCES`에 적고, 화면에는 출력하지 않아요.

**보고 기한(사안 접수 후 24시간 이내 교육지원청 보고, 사안 보고 후 5일 이내 발생보고서·주말·공휴일 제외)**은
법률이 아니라 매뉴얼 기준이에요(법률은 ‘지체 없이’). 교육부 매뉴얼(2026)과 서울·인천 2026 매뉴얼에서 같은 기준을 확인했어요.
경기 2026 종합대책에는 기한이 따로 적혀 있지 않고 교육부 매뉴얼을 따라요.
새 지역을 추가할 때 그 지역 매뉴얼 기한이 다르면 공통에서 빼 지역 데이터로 옮기세요.

지역마다 달라지는 값은 문장 안에 토큰으로 적어요. 화면에 그릴 때 선택한 지역 값으로 바뀌어요.

| 토큰 | 뜻 | 예(인천) |
| --- | --- | --- |
| `{HOT}` | 대표번호 | 032-1395 |
| `{HOT1}` | 법률·심리·치료 문의 번호 | 032-1395(1번) |
| `{HOT2}` | 신고·심의 문의 번호 | 032-1395(2번) |
| `{OFFICER}` | 학교 내 교육활동 보호 담당자 | 교권보호책임관(교감) |
| `{LEGAL}` | 법률 지원 조직 이름 | 법률지원단·교권전담변호사 |
| `{MUTUAL}` | 학교안전공제회 | 인천학교안전공제회 |
| `{SOS}` | 학교민원 지원 조직 | 학교민원 SOS 지원단 |
| `{MEDIATE}` | 갈등 조정 사업 | 교육활동 갈등중재 지원 |

- 지역을 아직 고르지 않았거나, 지역 데이터에 해당 값이 없으면 `NEUTRAL_TERMS`의 중립 문구가 들어가요.
  **다른 지역의 값으로 대신 채우지 않아요.**
- 토큰 바로 뒤에 조사(이/가, 은/는, 와/과)를 붙이지 마세요. 지역마다 받침이 달라 문장이 어색해져요(‘에게’, ‘에서’, ‘의’는 괜찮아요).
- 전국 공통 긴급번호(112)만 공통 데이터에 직접 적어요.

### 지역 데이터(`data/regions/*.js`)

각 파일은 `registerRegion({...})`으로 자신을 등록해요. 필수 항목이 빠지면 콘솔에 오류를 남기고 등록하지 않아요.

| 항목 | 설명 |
| --- | --- |
| `id` | 내부 id(영문, 바꾸지 않기). 저장·주소(`?region=`)에 쓰여요 |
| `short`, `name`, `office`, `officeUrl` | 표시 이름, 정식 이름, 시·도교육청, 홈페이지 |
| `basis` | 기준 자료 이름(예: 「2026 … 시행계획」) |
| `verifiedAt`, `sources` | 최종 확인일과 공식 출처 목록 `{ title, url, verifiedAt, uses }`. `uses`는 이 자료를 근거로 보여 줄 화면이에요: `guide`(상황별 도움), `procedure`(대응 절차), `support`(지원 찾기), `finder`(교육지원청 찾기) |
| `hot`, `hotName`, `hotSummary` | 대표번호와 이름·한 줄 설명 |
| `menu` 또는 `menuNote` | 확인된 ARS 메뉴 목록. 모르면 `menuNote` 한 줄만 |
| `links` | 지원 찾기 상단 ‘지역 지원 허브’의 바로 이용하기 `{ type: 'apply' | 'kakao' | 'guide', label, url }`. 시·도교육청 홈페이지(`officeUrl`)는 자동으로 붙어요 |
| `terms` | 위 토큰 값. 확인 못 한 항목은 **빼 두기**(중립 문구로 표시돼요) |
| `offices` | 교육지원청 `{ name, dept?, areas: [시·군·구], contact?, hours?, url?(홈페이지), guideUrl?(교육활동보호 안내 페이지) }` |
| `expectedAreas` | 공식 행정구역 수(점검 도구가 `areas` 합계와 비교해 누락을 찾아요) |
| `areaNote` | 관할 변경 예고 등 ‘내 교육지원청 찾기’에 보여 줄 안내(선택) |
| `programs` | 지원 찾기의 지원 항목. `area`는 `SUPPORT_TYPES`의 유형에 연결돼야 하고, `source`에 `sources` 배열 번호를 적으면 ‘근거 자료’ 링크가 붙어요 |
| `programs[].channels` | 실제 행동 경로 `{ type: 'apply' | 'kakao' | 'guide', label?, url }`. 전화 버튼은 `contact`의 첫 번호로 자동으로 만들어져요 |
| `orgs` | 지원 찾기 하단 ‘기관 연락처’ 목록 |

값을 모르는 필드(`contact`, `apply` 등)는 비워 두세요. 화면에 **‘공식 안내 확인 필요’**로 표시돼요.

### 근거 자료(source)와 행동 경로(channels)를 구분해요

- `source`/`sources`: 정책이 맞다는 **근거**(시행계획·매뉴얼·보도자료). 카드 아래 ‘근거 자료’로 보여요.
- `channels`: 교사가 실제로 **신청·상담·안내**받는 곳. 버튼으로 보이고 우선순위는 온라인 신청 → 전화 → 카카오톡 → 공식 안내예요(카드당 최대 3개).
- `apply`는 공식 사이트에서 **실제 신청이 이뤄지는 페이지**일 때만 넣어요. 로그인이 필요하면 label에 적어요(예: ‘온라인 신청(로그인)’).
  확인할 수 없으면 만들지 말고 전화·공식 안내만 두세요. 추측한 URL은 넣지 않아요.
- 링크는 https + 공식 기관 도메인(`*.go.kr`, 시·도 학교안전공제회, 경기 교육지원청 도메인, KEDI, 공식 자료가 안내한 카카오톡 채널)만 허용되고,
  `tools/check-data.js`가 검사해요. 새 기관 도메인은 공식 출처를 확인한 뒤 `OFFICIAL_HOSTS`에 추가하세요.

## 새 시·도 추가하기(예: 부산)

1. `data/regions/incheon.js`를 복사해 `data/regions/busan.js`를 만들고 `id: 'busan'`, 이름·교육청을 바꿔요.
2. 시·도교육청 공식 자료로 확인한 내용만 채워요. `sources`에 출처를, `verifiedAt`에 확인한 날짜를 적어요.
   확인하지 못한 번호·사업·기한은 비워 둬요(추측해서 채우지 않기).
3. `offices`에 교육지원청과 관할 시·군·구(`areas`)를 적고 `expectedAreas`에 공식 행정구역 수를 적어요.
   관할 근거는 아래 ‘교육지원청 관할 근거’를 보세요.
4. `index.html`의 지역 스크립트 목록에 `<script src="data/regions/busan.js"></script>` 한 줄을 추가해요(적은 순서 = 선택 목록 순서).
5. `node tools/check-data.js`로 점검하고, 로컬에서 부산을 선택해 대표번호·교육지원청 찾기·지원 찾기 화면을 확인해요.

`app.js`와 `data/common.js`는 고칠 필요가 없어요.

## 교육지원청 관할 근거

「지방교육자치에 관한 법률」 개정으로 2026. 5. 12.부터 교육지원청 관할구역은 **시·도 조례**로 정해요.
시행령 [별표 2]는 삭제됐고, 부칙(대통령령 제36292호) 제2조에 따라 조례를 만들기 전까지는 종전 [별표 2]가 적용돼요.

| 지역 | 현재 근거 | 메모 |
| --- | --- | --- |
| 서울 | 종전 시행령 [별표 2] | 11개 교육지원청 · 25개 자치구 |
| 경기 | 「경기도교육청 행정기구 설치 조례」 [별표 9] | 25개 교육지원청 · 31개 시·군. 통합 교육지원청 분리 추진 중 |
| 인천 | 종전 시행령 [별표 2]를 2026. 7. 1. 개편 구역에 적용 | 5개 교육지원청 · 2군 9구(아래) |

인천은 2026. 7. 1. 행정체제 개편으로 중구·동구·서구가 없어지고 제물포구·영종구·서해구·검단구가 생겼어요.

- 남부: 미추홀구·제물포구·영종구·옹진군 / 북부: 부평구·계양구 / 동부: 남동구·연수구 / 서부: 서해구·검단구 / 강화: 강화군
- 2027. 3. 1. 영종·검단교육지원청 신설과 서부 → 서해교육지원청 개칭이 입법예고 중이에요(교육청공고 제2026-385호). 시행되면 `incheon.js`의 `offices`와 `areaNote`를 고치세요.

## 데이터 출처·확인일 규칙

- 근거는 시·도교육청·교육지원청 공식 홈페이지, 공식 시행계획·매뉴얼, 교육청 보도자료 순으로 써요.
  개인 블로그·카페 글은 근거로 쓰지 않아요.
- 정보를 새로 확인하거나 고치면 해당 `sources[].verifiedAt`과 지역 `verifiedAt`을 그날 날짜(`YYYY-MM-DD`)로 바꿔요.
  화면의 ‘최종 확인’ 날짜가 이 값으로 표시돼요.
- 새 출처는 `sources` 배열 **끝에만** 추가해요. 중간에 넣으면 `programs[].source` 번호가 어긋나요.
- 화면마다 ‘안내 근거 · 지역’에는 선택한 지역 자료 중 `uses`가 맞는 것만 보이고, 전국 공통 근거는 그 아래 ‘공통 법적·정책 근거’로 작게 붙어요.
  지역을 고르지 않으면 ‘공통 안내 근거’만 보여요. 다른 시·도 자료는 어느 지역 화면에도 섞이지 않아요.
- 출처 URL은 교육청 메인 홈페이지보다 실제 근거 문서(매뉴얼 PDF, 사업 안내 페이지, 보도자료)를 우선해요.
  메인 홈페이지만 적으면 점검 도구가 주의를 표시해요.
- 오래된 정보를 찾을 때는 `verifiedAt`을 검색하면 돼요.
- ARS 메뉴 번호는 해당 연도 공식 자료에 적혀 있을 때만 `menu`에 넣어요. 없으면 `menuNote`만 써요.
- 전화번호는 위기 상황에서 쓰여요. 번호를 바꿨다면 실제로 걸어 보거나 공식 자료와 다시 대조해 주세요.

### 배포 전 점검

```bash
node tools/check-data.js
```

필수 항목·출처 번호·확인일 형식, 교육지원청 관할 중복·누락(`expectedAreas`와 비교), 전화번호 형식, 지역 간 전화번호 혼입,
지원 항목의 유형 연결, 세부 상황의 큰 상황 연결, 신청·안내 링크의 https·공식 도메인, 출처의 `uses`와 공통 근거의 지역 자료 혼입,
공통 데이터의 지역 번호를 검사해요. 문제가 있으면 종료 코드 1로 끝나요.

## 로컬에서 확인하기

`index.html`을 파일로 바로 열어도 대부분 동작하지만, 실제 배포와 같게 보려면 간단한 정적 서버를 쓰세요.

```bash
npx serve .
```

주소 뒤에 `?region=seoul`처럼 붙이면 그 지역으로 바로 열려요.

## 저장하는 정보

사용자 기기의 localStorage에만 저장돼요(서버 전송 없음).

- `teacher-care-region`: 선택한 지역 id(알 수 없는 값이면 무시하고 지워요)
- `teacher-care-procedure-checks-v1`: 대응 절차 진행 체크 `{ '단계번호.항목id': true }`. 항목 id(`STEP_DETAIL[].checks[].id`)는 문구를 고쳐도 바꾸지 마세요.
- 예전 체크리스트 키(`teacher-care-checks`, `icn-gyeote-checks`)는 삭제된 목록의 순번으로 저장돼 새 항목과 맞지 않아 옮기지 않고 지워요.

## 배포

`main` 브랜치가 GitHub Pages로 배포돼요(`.nojekyll` 포함). 작업은 기능 브랜치에서 하고 검토 후 `main`에 합쳐요.
